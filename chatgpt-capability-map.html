Prompting — biggest levers first

GPT‑5.6 understands intent well; give it the outcome, boundaries and success checks instead of micromanaging every thought.

⚖️

Speed vs depth

In ChatGPT: Instant uses GPT‑5.5; Medium, High and Extra High use GPT‑5.6 Sol; Pro uses GPT‑5.6 Sol Pro. In the API, model and reasoning effort are independent controls.
📏

High-leverage operating rules

Surface first

Chat answers. Work owns knowledge-work outcomes. Codex owns software outcomes. Do not force the wrong surface.

Search vs research

Search for a current fact. Deep research for multi-source synthesis with a plan, progress and citations.

Evidence before confidence

For current or high-stakes claims, specify sources and ask for citations. Fluency is not verification.

Give a check

Tests, a rubric, formulas, source constraints or a visual review let the agent correct itself.

Reuse structure

Project for context; skill for a repeatable method; plugin for a packaged workflow; scheduled task for repetition.

Escalate deliberately

Move from Instant → Sol → Pro only when task difficulty and error cost justify the added latency or usage.

🔐

Safety & compatibility gotchas

⚡ Model, surface and tool availability differ. A capability may be blocked by plan, region, workspace policy or rollout even when the model supports it.
⚡ Canvas is not supported by GPT‑5.5-or-later models. Use Work/Codex deliverables or select a compatible model when Canvas itself is required.
⚡ Apps are not available with Pro models. Use standard reasoning when the task depends on connected app data or actions.
⚡ Deep research uses read actions only. Use Work or a normal app-enabled chat when the outcome requires an external write.
⚡ Browser content is untrusted. Confirm the active account, enter credentials only in the browser, and review consequential actions.
⚡ Automation compounds mistakes. Start with low-risk, reviewable tasks and explicit notification/stop conditions.
